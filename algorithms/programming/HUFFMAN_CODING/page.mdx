## 1 · The question

The ask is a code: one distinct bit string per symbol, so that the encoded stream is short and decodes without separators. Common symbols should get short strings, so you are minimising the average length $\sum_i p_i \ell_i$ over all assignments of strings.

Brute force would try every assignment. The reason it is the wrong picture is that the strings are not independent — some assignments of lengths cannot be realised by any prefix-free code at all. The question is which lengths are allowed and which tree attains the best ones.

## 2 · The real object: a binary tree with the symbols at its leaves

A prefix-free code, one where no code word begins another, is exactly a binary tree with the symbols at the leaves. The path from the root to a leaf spells that symbol's code word: left is 0 and right is 1. So the code and the tree are one object, and the length $\ell_i$ is the leaf's depth.

Prefix-freedom is then automatic. A symbol sits at a leaf, no leaf is an ancestor of another, so no code word is a prefix of a different one, and decoding walks the tree reading bits until it lands on a leaf.

The payoff of the tree view is a second way to add up the cost. Each leaf is counted once for every internal node above it, so regrouping the sum by internal nodes gives an identity.

$$
\sum_i p_i \ell_i \;=\; \sum_{\text{internal } v} w(v).
$$

The panel is this identity in motion: every merge creates one internal node, and the running total is the weight of that node added in. When one tree remains the total is the average code length, and until then it is a partial sum.

## 3 · The mathematics: entropy below, one bit above

**Shannon 1948.** The entropy of the source is

$$
H \;=\; -\sum_i p_i \log_2 p_i,
$$

and no uniquely decodable code has average length below $H$. For a prefix code the depths must satisfy Kraft's inequality (Kraft 1949),

$$
\sum_i 2^{-\ell_i} \le 1,
$$

and McMillan 1956 showed the same inequality holds for every uniquely decodable code, prefix or not.

Together those give the floor. Any lengths obeying Kraft satisfy $\sum_i p_i \ell_i \ge H$, so the axis cannot drop below the $H$ marker: every tree the panel can build has valid depths, and valid depths cost at least $H$.

**Huffman 1952.** Merging the two lightest roots, over and over, produces a tree of minimum weighted path length $L^*$.

The reason is an exchange argument. Take any optimal tree; its two least probable symbols can be made siblings at the deepest level without raising the cost, by swapping them with the deepest pair. So some optimal tree merges the two lightest first, and recursion finishes the proof.

That bound and the floor sit one bit apart. Choosing the lengths $\ell_i = \lceil \log_2(1/p_i) \rceil$ costs at most $\log_2(1/p_i) + 1$ for each symbol and still obeys Kraft, so a prefix code exists with $L < H + 1$. Huffman's rule is optimal, hence

$$
H \;\le\; L^* \;<\; H + 1.
$$

Both ends of that inequality are honest in different ways. The floor is a theorem about all codes; the ceiling is a theorem about the greedy tree, and the gap between them can be as large as a whole bit.

## 4 · The centrepiece: price your own merges

Go back to the board and build the code yourself. Turn the hint off and merge a heavy root with a light one first, then finish greedily; the axis shows your accumulated cost drifting above the $L^*$ marker, and the final total is worse than the rule's.

Concretely, merging the weight-40 symbol with a weight-5 symbol first costs 45 bits of internal weight before any other merge, and the greedy finish lands at 2.45 against the rule's 2.25. That 0.20-bit spread is the greedy rule's value made visible, and no order does better.

Reset, turn the hint back on, and merge the two marked lightest roots each time. The lengths come out 1, 2, 3, 4, 5, 5 for the weights 40, 25, 15, 10, 5, 5, and the total stops exactly on the $L^*$ marker.

## 5 · The payoff

Every general-purpose compressor runs a Huffman stage. DEFLATE, the format inside gzip and PNG, sends a Huffman table for its literals and then a second one for its match lengths and distances, all built by this merge. JPEG quantises then Huffman-codes; MP3 does the same on its spectral coefficients.

The rule generalises without changing character. Merging the $k$ lightest roots at a time gives optimal $k$-ary codes, and when the code must fit a fixed field width, the package-merge method of Larmore and Hirschberg 1990 finds the best length-limited tree in nearly linear time.

## 6 · Optional: where the one-bit gap comes from, and how to beat it

Skippable. The gap is an artefact of whole-bit code words. When a symbol's probability is far from a power of a half the nearest dyadic length overshoots, and no prefix code can split a bit. On the two-symbol 0.99/0.01 source the rare symbol carries almost all of the entropy — 6.64 bits of surprise worth 0.066 of the total — yet it still costs a full bit, so the average length is 1 against an entropy of 0.0808.

Arithmetic coding removes the artefact by coding a whole message into one number instead of one symbol at a time, reaching the entropy in the limit (Rissanen 1976). It wins precisely where Huffman loses, which is why modern compressors keep both and pick per block.

## 7 · Attributions

- **Shannon 1948** — *A Mathematical Theory of Communication*: the entropy $H$ and the lower bound on the length of any decodable code.
- **Kraft 1949** — the inequality satisfied by the depths of a prefix code, the constraint on which lengths a tree can realise.
- **Fano 1949** — the top-down Shannon–Fano construction, the earlier method Huffman's rule improves on.
- **Huffman 1952** — *A Method for the Construction of Minimum-Redundancy Codes*: merge the two lightest roots, and the exchange lemma that makes the result optimal.
- **McMillan 1956** — the extension of Kraft's inequality to all uniquely decodable codes, not only prefix codes.
- **Gallager 1978** — *Variations on a theme by Huffman*: the redundancy of Huffman codes, and the $H \le L^* < H + 1$ bound analysed.
- **Rissanen 1976** — arithmetic coding, the method that reaches the entropy the one-bit bound leaves behind.
- **Larmore–Hirschberg 1990** — package-merge, the length-limited Huffman tree, for codes constrained to a fixed bit width.
