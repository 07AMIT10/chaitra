## Binary search is not looking at the middle. It is halving an interval of possible answers.

Eight sorted numbers sit in a row: `[3, 9, 14, 21, 27, 33, 41, 58]`. You want the 27.

You read index 3, see 21, and every index at or below 3 is ruled out, because the row is sorted and nothing there can reach 27. You read index 5, see 33, and everything at or above 5 goes with it. Index 4 is the 27.

## 1 · The question

Given a sorted sequence $a_0 \le a_1 \le \dots \le a_{n-1}$ and a target `t`, return an index `i` with $a_i = t$, or report that `t` is absent. The operational description is a loop: look at the middle, go left or go right, repeat. That description tells you what to type; it says nothing about why the loop is fast.

The naive answer is a scan from the left, which costs up to `n` comparisons. The interesting question is not which element to read next. It is how much of the candidate set one comparison is allowed to delete.

## 2 · The real object: the interval of surviving candidates

The state of binary search is an interval of indices that might still hold the answer, together with the knowledge that every index outside it does not. Write it $[lo, hi)$. Nothing else is stored: no counter, no path, no visited set.

$$ \left(\exists i : a_i = t\right) \implies \exists i \in [lo, hi) : a_i = t $$

Sortedness is what makes a deletion legal. If $a_{mid} \lt t$ and the array is sorted, then $a_j \le a_{mid} \lt t$ for every $j \le mid$, so one comparison rules out a whole prefix. If $a_{mid} \gt t$ the same argument rules out a whole suffix.

A probe takes $mid = \lfloor (lo+hi)/2 \rfloor$ and moves one endpoint, after which the surviving length `r` is at most $\lfloor r/2 \rfloor$.

The midpoint is a detail of the halving, not the subject of the algorithm. What the loop maintains is an interval that cannot lose the answer, and what it does is shrink that interval by a factor of two.

## 3 · The mathematics

**The recurrence.** A probe costs one comparison and leaves an interval at most half as long. If $T(n)$ is the worst-case comparison count on `n` candidates,

$$ T(n) = T(\lfloor n/2 \rfloor) + 1, \qquad T(1) = 1 $$

Substitute the sizes that are powers of two, $n = 2^k$, and the recurrence unwinds into a count of halvings:

$$ T(2^k) = T(2^{k-1}) + 1 = k + T(1) = k + 1 $$

Solving back for `n` gives a closed form that is an identity, not an estimate:

$$ T(n) = \lfloor \log_2 n \rfloor + 1 = \lceil \log_2 (n+1) \rceil $$

This is the balanced case of the master theorem with $a = 1$, $b = 2$, $d = 0$ (Bentley, Haken and Saxe 1980). Because $n^d = 1$ here, the case's $\Theta(n^d \log n)$ is $\Theta(\log n)$.

**The bound, and the model it lives in.** Everything so far is a statement about comparisons. Say the model out loud: the algorithm learns about the data only by comparing one stored value with the target, and each comparison returns one of at most two answers. That is the comparison model.

Inside it, picture every run the algorithm can take as a decision tree. A run of `k` probes asks `k` two-outcome questions, so it can end at no more than $2^k$ leaves.

The answer set has `n + 1` elements: the `n` positions, plus "absent". A correct search must end at a different leaf for each answer, so

$$ 2^k \ge n + 1 \quad\Longrightarrow\quad k \ge \lceil \log_2 (n+1) \rceil $$

That is the count the recurrence produced, so binary search is not merely fast: in the comparison model it is exactly optimal, and the argument is the decision-tree lower bound (Knuth 1973, §5.3.1). Keep it separate from Shannon's source-coding bound — that one counts entropy, this one counts leaves.

The fine print is the model. If the only way you may look at the data is a comparison, $\Omega(\log n)$ is the floor. The payoff below names the ways out of that model.

On a logarithmic axis the halving curve is a straight line: each probe subtracts the same $\log_2 2 = 1$ from the log of the candidate count, and the line meets the axis where the count reaches one. The scan curve is level, because deleting one candidate is invisible against a billion. The logarithm is nothing more than the x-coordinate where the first line bottoms out.

**The boundary is the object.** Drop the array and keep the predicate. Let `P` be a predicate on $\{0,\dots,n-1\}$ that is false up to some point and true from there on: false, false, …, true, true. With `b` the first index where `P` is true, binary search finds `b`.

Sorted search is the case $P(i) = (a_i \ge t)$, whose boundary is the first index reaching `t`. Root-finding is the case where `f` is monotone and $P(x) = (f(x) \ge 0)$, whose boundary is the root.

Bisection is that halving on a real interval, narrowing width `w` to $\varepsilon$ in $\lceil \log_2 (w/\varepsilon) \rceil$ steps. Search and bisection are one algorithm with two readings of `P`.

**The hazard is the arithmetic.** The proof above hides the real difficulty, which is endpoint arithmetic. A closed interval $[lo, hi]$, a half-open one $[lo, hi)$, and a both-ends-inclusive loop with $hi = mid - 1$ each need their own update, and mixing them is how the loop either skips the answer or never stops. Bentley 1986 reported that a large majority of the programmers he tested wrote binary search wrong on the first attempt, and the errors are nearly always off-by-ones in the endpoints, not a misunderstanding of halving.

The invariant is the test. Write down "the answer, if present, lies in the interval", then check that each branch preserves it and that the length strictly decreases. A branch that keeps the length the same is the infinite loop; a branch that moves an endpoint one index too far is the missed answer.

Set the slider to $a = 2$ and the panel flips to the leaf-dominated case, $\Theta(n)$: recursing into both halves turns the search into a linear scan. The logarithm is not bought by the halving. It is bought by the $a = 1$, the discarding of one half on every probe.

Now push $d$ instead. Raising $d$ makes each node's own work polynomial and moves the panel out of the balanced case; the search you are driving is the $d = 0$ slice, where a probe is one comparison. Set $b = 4$ and the halving is by a factor of four, which shortens the tree but changes only the base of the logarithm, not its shape.

## 5 · The payoff

The same boundary search appears wherever a monotone predicate splits a domain.

- C++'s `lower_bound` and `upper_bound`, and Python's `bisect_left`, return the first index that is not less than the key: that is the boundary `b` for the predicate $a_i \ge t$.
- `git bisect` runs the loop over commits, with "does the bug reproduce here?" as the predicate; one test halves the suspects.
- Bisection for a root of a monotone `f` evaluates the sign of `f(mid)` where the search compares values, and narrows the bracket by half each step.
- Binary lifting walks a tree by searching over an exponent range, which is this halving over a node's ancestors.

Now the honest limit. The $\Omega(\log n)$ floor is a comparison-model floor: a fact about the access model, not about information in the abstract. Leave the model and the floor moves.

- Interpolation search reads the values and their order together, and finds a uniformly distributed key in $O(\log \log n)$ expected comparisons (Peterson 1957).
- A hash table answers membership in $O(1)$ expected by discarding order entirely.
- A van Emde Boas tree reads the bits of an integer key and answers predecessor queries in $O(\log \log U)$ over a universe `U` (van Emde Boas 1975).

So the logarithm is the price of learning the data one binary question at a time. Change what a question may be, and the price changes with it.

## 6 · Advanced and optional

Skip this section if you want the main line; nothing below is used again.

**The overflow bug.** In fixed-width arithmetic, $(lo + hi)$ overflows before the division does, for arrays larger than half the integer range. The safe midpoint is $lo + \lfloor (hi - lo)/2 \rfloor$. The bug lived in Java's `Arrays.binarySearch` for nine years (Bloch 2006).

**One comparison, three answers.** If a single comparison reports less, equal, or greater, the tree is ternary and the leaf bound becomes $3^k \ge 2n + 1$, so $k \ge \log_3 (2n + 1)$. The constant is smaller and the logarithm is the same. The two-outcome model is the one that matches "one yes/no per probe".

**The comparison profile is not flat.** For `n = 15`, one position costs 1 comparison, two cost 2, four cost 3, and the remaining eight cost 4. Half the positions sit at the deepest level, and the average is about 3.27 comparisons. The tree's bottom is where the expense is, which is why the average stays close to the worst case at small `n`.
